# 여행 노트 앱 설계 (1단계)

작성일: 2026-11-14 · 상태: 승인 대기

## 1. 의도

계획 → 실행 → 기록이 하나로 이어지는 여행 앱. 여행 전에 짠 일정이 여행 중에는 길잡이가 되고, 도착 시간·사진·메모·비용·스탬프가 쌓이면서 여행이 끝나면 그대로 여행 일기가 된다.

만드는 사람은 디자이너(HTML/CSS 가능, 개발 경험 없음)이며, 앱 개발부터 앱스토어 등록·심사·출시까지 전 과정을 직접 경험하는 것도 목표다. 정식 서비스로 키울지는 미정.

출발점이 된 불편(트리플):
- 하루 경로가 길면 지도가 줌아웃되고, 확대해서 보다가 다음 구간을 누르면 다시 줌아웃된다.
- 경로가 직선으로 그어진다.
- 길이 "최단"뿐이다. 여행 중에는 가게 많은 길, 풍경 좋은 길, 안전한 길을 고르고 싶다.

## 2. 목표 / 하지 않는 것 / 실패 조건

**1단계 목표**
- 본인 아이폰으로 실제 해외여행에서 쓸 수 있다.
- 앱스토어 심사를 통과해 출시된다.
- 2단계 기능(길 고르기 등)을 구조 변경 없이 얹을 수 있다.

**1단계에서 하지 않는 것**
- 길 고르기, 사진 자동 연결, 카드 문자 인식, 일기 넘겨보기 화면, 다이나믹 아일랜드·위젯 (2단계)
- 항공편·공항 안내, 한국 특화(네이버·카카오·티맵), 안드로이드 (3단계)
- 회원가입, 서버, 기기 간 동기화, 공유

**실패 조건 (기능이 돌아가도 실패)**
- 사용자가 맞춘 지도 확대 상태가 사용자의 명시적 동작 없이 바뀐다.
- 경로가 직선으로 그려진다.
- 일반적인 지도 앱처럼 보인다. 문구류·아날로그 감성이 없다.
- 여행 중 일정 고치기가 번거롭다.

## 3. 제약

- 기기: 아이폰 (개발은 맥). 첫 출시는 애플 앱스토어.
- 지도·장소·경로 데이터: 구글 (해외여행 기준).
- 아이폰은 앱이 문자를 읽을 수 없다 → 카드 문자는 2단계에서 붙여넣기/공유 인식으로.
- 아이폰은 동시에 감시할 수 있는 장소 반경이 20개로 제한된다.
- 구글 장소 정보는 장기 저장이 약관상 제한된다.
- 구글 API는 사용량 과금. 개인 사용은 무료 한도 내로 예상.

## 4. 검토한 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 엑스포(리액트 네이티브)** — 선택 | 코드 한 벌로 아이폰·안드로이드. 스타일이 CSS와 유사해 디자이너가 직접 손볼 수 있음. 도착 감지·지도·사진 지원. 빌드·스토어 제출 자동화 | 위젯·다이나믹 아일랜드 화면은 소량의 Swift가 별도로 필요 |
| B. 아이폰 전용(Swift) | 아이폰 기능을 가장 깊게 사용 | 안드로이드는 재작성. 화면 코드를 디자이너가 고치기 어려움 |
| C. 웹을 앱으로 포장 | 기존 HTML/CSS 지식 그대로 | 지도 성능과 백그라운드 도착 감지가 약함. 심사 거절 위험 |

사용자는 만드는 방식을 맡겼고, 빌더의 판단으로 A를 선택했다. 사용자가 확인한 요구: 아이폰 고유 기능(애니메이션, 다이나믹 아일랜드, 위젯)을 쓸 수 있어야 한다 → A에서 가능하며 2단계에 배치.

## 5. 사용자가 정한 것

- 첫 대상은 구글 지도 중심의 해외여행.
- 아이폰 + 맥, 앱스토어 출시까지 경험.
- 길 고르기는 꼭 필요하지만 1단계 이후 추가해도 됨.
- 디자인: 감성적인 일러스트 풍. 도시·랜드마크는 사진보다 라인 그래픽. 문구류·아날로그 감성. 방문 스탬프.

## 6. 1단계 기능

### 6.1 여행과 일정
- 여행 만들기: 이름, 도시, 기간, 기준 통화.
- 날짜별 일정. 장소는 구글 장소 검색으로 추가하거나 지도에서 길게 눌러 추가.
- 순서는 끌어서 변경, 다른 날로 이동, 삭제. 여행 중에도 같은 방식으로 고친다.
- 장소마다 예정 시간(선택), 메모.

### 6.2 장소 정보
- 장소를 누르면 구글의 별점, 리뷰 수, 사진, 영업시간, 주소, 웹사이트를 보여준다.
- 볼 때마다 가져오고 짧게만 임시 보관한다 (약관).

### 6.3 지도와 경로
- 하루 일정의 장소를 순서대로 잇는 경로를 실제 길을 따라 그린다.
- 구간(장소 A → B)마다 이동 수단(도보/대중교통/차)을 정할 수 있다. 기본은 도보.
- 구간별 거리와 예상 시간 표시.
- **지도 화면 규칙**: 지도는 다음 세 경우에만 스스로 움직인다.
  1. 그날의 지도를 처음 열 때 (전체 경로가 보이게)
  2. "전체 보기" 버튼을 눌렀을 때
  3. "현재 위치" 버튼을 눌렀을 때
- 구간이나 장소를 선택하면 지도는 움직이지 않고 선택된 것만 강조된다. 선택한 것이 화면 밖에 있으면 화면 가장자리에 방향 표시와 "여기로 이동" 버튼이 나타나며, 누를 때만 현재 확대 수준을 유지한 채 이동한다.
- 지도 색감은 구글 지도 맞춤 스타일로 종이 지도 느낌에 맞춘다.

### 6.4 도착 기록과 스탬프
- 오늘 일정의 장소 반경(기본 150m)에 들어오면 앱이 꺼져 있어도 도착 시간을 기록하고 알림을 보낸다.
- 도착하면 그 장소에 스탬프가 찍힌다 (날짜·시간이 들어간 소인 형태).
- 위치 권한을 "항상 허용"으로 주지 않았거나 감지가 안 된 경우, 손으로 "도착" 체크 가능. 시간은 고칠 수 있다.
- 20개 제한: 오늘 일정 중 아직 방문하지 않은 장소를 현재 위치에서 가까운 순으로 20개까지 등록하고, 도착할 때마다 다시 계산한다.

### 6.5 기록
- 방문지마다 사진(사진첩에서 고르거나 촬영), 글 메모를 남긴다.
- 일정에 없던 곳도 "지금 여기"로 바로 추가해 기록할 수 있다.

### 6.6 비용
- 방문지마다 비용 여러 건 입력: 금액, 통화, 분류(식비/교통/쇼핑/입장료/숙박/기타), 메모.
- 장소에 묶이지 않는 비용도 날짜에 입력 가능.
- 하루 합계, 여행 전체 합계, 분류별 합계. 기준 통화로 환산 (환율은 여행 설정에서 직접 입력).

## 7. 구조 (빌더의 판단)

- 엑스포 + 타입스크립트. 개발용 빌드를 사용한다 (백그라운드 위치와 구글 지도 때문에 엑스포 고 앱으로는 부족).
- 지도: react-native-maps, 구글 제공자. 경로: 구글 Routes API. 장소: 구글 Places API (New).
- 저장: 기기 안 SQLite. 사진은 앱 저장 공간에 사본을 둔다.
- 도착 감지: expo-location 지오펜싱 + expo-task-manager, 알림은 expo-notifications.
- 애니메이션: react-native-reanimated (스탬프 찍힘, 카드 전환).
- 언어: 한국어 우선, 문구는 분리해 두어 영어 추가 가능하게.

**데이터 모양**

- 여행(Trip): 이름, 도시, 시작일·종료일, 기준 통화, 환율표
- 하루(Day): 여행, 날짜
- 방문지(Stop): 하루, 순서, 구글 장소 ID, 이름, 좌표, 예정 시간, 도착 시간, 도착 방식(자동/수동), 메모
- 구간(Leg): 출발 방문지, 도착 방문지, 이동 수단, **후보 경로 목록**, 선택된 후보
- 후보 경로(RouteOption): 종류(1단계는 "기본"만; 2단계에 "가게 많은 길/풍경/안전/빠른 길" 추가), 경로 선 좌표, 거리, 시간
- 사진(Photo): 방문지, 파일, 촬영 시각, 좌표
- 비용(Expense): 여행, 날짜, 방문지(선택), 금액, 통화, 분류, 메모

구간이 "후보 여러 개 중 하나를 고른 것"으로 저장되므로, 2단계 길 고르기는 후보를 더 만들어 넣는 작업이 된다.

**구글 약관 대응**: 일정에는 장소 ID·이름·좌표만 저장하고, 별점·사진·영업시간은 볼 때 가져온다. 받아온 경로는 일정이 바뀌기 전까지 기기에 보관해 요금과 데이터 사용을 줄인다.

**API 키**: 1단계에서는 앱 안에 키를 넣되 사용 API를 제한하고 일일 한도를 걸어둔다. 불특정 다수에게 공개하기 전에는 키를 숨기는 작은 중계 서버로 옮긴다 (공개 범위를 넓힐 때의 선행 작업).

## 8. 화면 구성 (뼈대)

1. 여행 목록 — 여행을 노트 표지처럼 나열
2. 여행 홈 — 날짜 탭, 하루 요약(방문지 수, 이동 거리, 비용)
3. 하루 화면 — 위는 지도, 아래는 끌어올리는 일정 목록. 목록과 지도 선택이 연동
4. 장소 상세 — 구글 정보 + 내 기록(스탬프, 사진, 메모, 비용)
5. 장소 검색/추가
6. 비용 요약
7. 설정 — 권한 안내, 통화·환율

시각 디자인(색, 글꼴, 일러스트·스탬프 스타일)은 이 문서 승인 후 시안으로 따로 정한다.

## 9. 출시까지의 길

1. 깃허브 저장소 생성, 맥에 개발 환경 설치
2. 구글 클라우드 계정과 API 키 발급
3. 본인 아이폰에 개발용 빌드 설치 (애플 개발자 등록 연 99달러 — 백그라운드 위치를 실기기에서 쓰려면 이 시점에 필요할 수 있음)
4. 기능 구현 → 동네에서 실사용 테스트 (도착 감지는 실제로 걸어봐야 검증됨)
5. 테스트플라이트로 베타 설치
6. 스토어 등록 정보(스크린샷, 설명, 개인정보 처리방침, 위치 "항상 허용" 사용 사유) 작성 → 심사 → 출시

심사에서 주의할 점: 백그라운드 위치 사용 사유를 분명히 써야 하고, 구글 지도 출처 표기를 가리면 안 된다.

## 10. 이후 단계

**2단계**
- 길 고르기: 구간마다 후보 경로 여러 개를 받아 주변 가게·식당·공원·물가 밀도, 큰길 여부 등으로 점수를 매겨 "빠른 길/가게 많은 길/풍경 좋은 길/안전한 길"로 제시
- 사진첩에서 촬영 시각·위치로 방문지에 자동 연결
- 카드 문자 붙여넣기/공유 → 금액·가맹점 인식
- 일기처럼 넘겨보는 화면
- 다이나믹 아일랜드(다음 목적지, 남은 거리)와 홈 화면 위젯(오늘 일정, 오늘 쓴 돈)

**3단계**
- 항공편 정보, 공항 안내(직접 정리한 콘텐츠), 시내 이동 방법
- 한국 특화: 네이버 지도, 카카오 장소, 티맵 도보 경로
- 안드로이드, 백업·동기화

## 11. 빌더에게 남긴 것

- 화면 전환과 세부 인터랙션
- 오류·오프라인 상태 처리 (해외에서 데이터가 끊겨도 저장된 일정·경로·기록은 보여야 한다)
- 도착 반경과 재계산 시점의 미세 조정
- 테스트 범위
